# Skill Naming Conventions

Guidelines for naming Clawdbot Skills consistently and professionally.

## General Rules

### Format
- **Kebab-case**: All lowercase with hyphens separating words
- **Length**: 2-5 words maximum
- **Style**: Descriptive but concise
- **Domain**: Use domain-specific terms when appropriate

### Naming Goals
- Instantly convey the skill's purpose
- Be easy to remember and type
- Differentiate from generic tools
- Appeal to target users

## Decision Framework

### Step 1: Identify the Core Action

What is the primary action the skill performs?

**Common Action Words:**
- Generate, Create, Make → `*-generator`, `*-creator`, `*-maker`
- Write, Draft, Author → `*-writer`, `*-drafter`, `*-author`
- Analyze, Review, Check → `*-analyzer`, `*-reviewer`, `*-checker`
- Clean, Fix, Repair → `*-cleaner`, `*-fixer`, `*-repair`
- Schedule, Plan, Organize → `*-scheduler`, `*-planner`, `*-organizer`
- Convert, Transform, Process → `*-converter`, `*-processor`, `*-transformer`
- Extract, Parse, Read → `*-extractor`, `*-parser`, `*-reader`

### Step 2: Identify the Domain/Object

What is the skill working with?

**Common Domains:**
- Email, Slack, Messages → `email-*`, `slack-*`, `message-*`
- Code, Scripts, Functions → `code-*`, `script-*`, `function-*`
- Images, Videos, Media → `image-*`, `video-*`, `media-*`
- Data, JSON, CSV → `data-*`, `json-*`, `csv-*`
- Text, Content, Writing → `text-*`, `content-*`, `writing-*`

### Step 3: Combine Action + Domain

**Pattern:** `[Action]-[Domain]` or `[Domain]-[Action]`

**Rule of Thumb:**
- Use `[Domain]-[Action]` when the domain is more distinctive
- Use `[Action]-[Domain]` when the action is the main feature

**Examples:**
- `email-drafter` (domain first = clearer)
- `code-reviewer` (domain first = clearer)
- `data-cleaner` (domain first = clearer)
- `prompt-optimizer` (domain first because "prompt" is the key concept)
- `meeting-scheduler` (domain first = clearer)
- `image-generator` (domain first = clearer)

**Action-first works better when:**
- The action is unique and specific
- Multiple domains could apply
- The action is the skill's main differentiator

Examples:
- `prompt-crafter` (not just any prompt tool, it "crafts" them)
- `style-transfer` (the action is the key feature)
- `knowledge-organizer` (organizing is the main benefit)

### Step 4: Refine and Polish

Check against the quality criteria:

**Clarity Test:**
- Does the name instantly tell you what it does?
- Would a new user understand it?

**Uniqueness Test:**
- Is it distinct from generic tools?
- Does it sound like a specific skill?

**Memorability Test:**
- Is it easy to remember?
- Is it easy to type?

**Brevity Test:**
- Is it 2-5 words?
- Are all words necessary?

## Naming Patterns by Use Case

### 1. Template-Based Skills
Pattern: `[Output-Type]-template` or `[Use-Case]-template`

Examples:
- `email-template`
- `resume-template`
- `invoice-template`
- `presentation-template`

### 2. Converter Skills
Pattern: `[Source]-to-[Target]-converter` or `[Source][Target]-converter`

Examples:
- `json-to-csv-converter`
- `markdown-to-html-converter`
- `pdf-to-text-converter`

### 3. Assistant/Helper Skills
Pattern: `[Domain]-assistant` or `[Domain]-helper`

**Prefer "assistant" over "helper"** (more professional)

Examples:
- `email-assistant`
- `coding-assistant`
- `research-assistant`
- `writing-assistant`

### 4. Optimizer/Improver Skills
Pattern: `[Target]-optimizer` or `[Target]-improver`

Examples:
- `prompt-optimizer`
- `code-optimizer`
- `performance-optimizer`
- `text-improver`

### 5. Detector/Checker Skills
Pattern: `[Target]-detector` or `[Target]-checker`

Examples:
- `plagiarism-detector`
- `bug-checker`
- `fact-checker`
- `quality-checker`

### 6. Generator/Creator Skills
Pattern: `[Output-Type]-generator` or `[Output-Type]-creator`

Examples:
- `image-generator`
- `code-generator`
- `content-creator`
- `idea-generator`

## Special Cases

### Multi-Word Domain
If the domain is multiple words, still use kebab-case:

✅ Good:
- `machine-learning-model-trainer`
- `user-interface-designer`
- `social-media-post-writer`

❌ Bad:
- `ml-model-trainer` (abbreviations unclear)
- `ui-designer` (abbreviations unclear)
- `social-post-writer` (unclear what "social" means)

### Acronyms
Avoid acronyms unless universally known and understood by the target audience.

✅ Acceptable acronyms:
- `api-integrator` (API is universally known)
- `url-shortener` (URL is universally known)
- `csv-processor` (CSV is universally known)

❌ Avoid:
- `ml-model-trainer` (use `machine-learning`)
- `ui-designer` (use `user-interface`)
- `crm-helper` (use `customer-relationship-management`)

### Brand Names
Generally avoid brand names unless:
- The skill is specifically for that brand
- The brand name is essential for clarity

✅ Acceptable:
- `slack-notifier` (specific to Slack)
- `salesforce-integrator` (specific to Salesforce)
- `shopify-product-uploader` (specific to Shopify)

❌ Avoid:
- `google-search-helper` (just `search-helper` is better)
- `microsoft-office-helper` (too broad)
- `amazon-product-finder` (too vague)

## Names to Avoid

### Generic Words
These words add no value and make skills indistinguishable:
- `AI`
- `helper`
- `tool`
- `assistant` (unless truly an assistant skill)
- `smart`
- `best`
- `pro`
- `ultimate`

### Promotional Language
Avoid marketing language in skill names:
- `the-best-email-writer`
- `ultimate-code-helper`
- `pro-social-media-tool`
- `amazing-ai-writer`

### Unclear or Slang
Avoid terms that could be misunderstood:
- `fixer` (what does it fix?)
- `stuff` (too vague)
- `thing` (too vague)
- `bot` (too generic)
- `app` (too generic)

### Numbers and Versions
Avoid unless necessary:
- `email-writer-2` (why is it 2?)
- `tool-v1` (version numbers belong in packaging)
- `code-helper-2024` (date doesn't belong in name)

## Verification Checklist

Before finalizing a skill name, verify:

- [ ] Is it kebab-case (lowercase, hyphens)?
- [ ] Is it 2-5 words?
- [ ] Does it instantly convey the skill's purpose?
- [ ] Is it descriptive without being verbose?
- [ ] Does it avoid generic words (AI, helper, tool)?
- [ ] Is it easy to type and remember?
- [ ] Does it use domain-specific terms when appropriate?
- [ ] Is it unique and distinctive?
- [ ] Does it avoid promotional language?
- [ ] Is there no clearer way to name it?

## Conclusion

A good skill name:
- **Clear**: Instantly communicates purpose
- **Concise**: 2-5 words, nothing extra
- **Descriptive**: Uses domain-specific terms
- **Professional**: Avoids slang and promotional language
- **Distinctive**: Not just another "AI helper"

When in doubt, prefer `[Domain]-[Action]` and ask: "Would a user understand what this skill does just from the name?"
