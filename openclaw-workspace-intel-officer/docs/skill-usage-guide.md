   - 发现新的情报源
   - 优化评分模型

## 🚀 Proactive-Agent (主动代理)

### 核心能力
将 AI 从任务执行者转变为主动伙伴，预测需求并持续改进

### 使用时机

#### ✅ 主动检查 (心跳时段)
**每 4 小时心跳检查时：**
1. **系统健康检查**
   - Gateway 运行状态
   - Cron 任务执行情况
   - 最近情报采集成功率

2. **任务堆积检查**
   - 检查是否有失败任务
   - 检查是否有超时任务
   - 检查推送是否成功

3. **情报价值检查**
   - 是否有突发热点需要立即推送
   - 是否有高价值选题 (>90 分) 需要优先处理

#### ✅ 主动发现 (情报采集后)
**每次情报采集完成：**
1. **热点分级**
   - P0 (95 分+): 立即推送 + 建议发布窗口
   - P1 (85-94 分): 写入选题池 + 晚间推送
   - P2 (70-84 分): 写入选题池备用

2. **时效性判断**
   - 突发热点 (发布<2 小时): 立即推送
   - 持续热点 (发酵中): 纳入晚间简报
   - 长尾内容: 写入选题池

3. **重复检测**
   - 检查是否与已有选题重复
   - 检查是否 24 小时内已推送
   - 检查是否有重大反转

#### ✅ 主动汇报 (特定场景)
**需要立即汇报：**
1. **系统异常**
   - Gateway 崩溃/重启
   - Cron 任务连续失败 (>3 次)
   - 推送成功率 <80%

2. **重要情报**
   - 突发热点热度>500 万
   - 与 OpenClaw/Cursor 直接相关
   - 可能影响发布计划的重大变化

3. **优化建议**
   - 发现新的监控源
   - 发现更高效的抓取策略
   - 发现配置问题需要修复

**不需要汇报 (静默执行)：**
- 常规心跳检查 (无异常)
- 常规情报采集 (无 P0 热点)
- 常规选题推送 (按流程执行)

## 📋 决策流程

### Self-Improvement 决策树
```
任务执行
    ↓
是否失败？ → 是 → 记录学习 → 更新配置/流程 → 继续
    ↓ 否
用户是否纠正？ → 是 → 记录学习 → 更新配置/流程 → 继续
    ↓ 否
发现更好方法？ → 是 → 记录学习 → 测试验证 → 应用
    ↓ 否
继续执行
```

### Proactive-Agent 决策树
```
心跳/采集完成
    ↓
检查系统状态
    ↓
是否有异常？ → 是 → 立即汇报 → 等待指令
    ↓ 否
是否有 P0 热点？ → 是 → 立即推送 → 建议发布窗口
    ↓ 否
是否有堆积任务？ → 是 → 主动清理 → 汇报结果
    ↓ 否
静默继续 (HEARTBEAT_OK)
```

### 案例 2: 选题定位偏差 (Proactive-Agent)
**触发:** 用户反馈 "选题定位不准"

**行动:**
1. ✅ 分析当前选题过滤规则
2. ✅ 对比公众号定位 (AI 实战/踩坑/测评/教程)
3. ✅ 发现推送了纯资讯类选题
4. ✅ 更新过滤规则排除纯资讯
5. ✅ 更新评分权重 (实战价值 40%)
6. ✅ 重新推送符合定位的选题

**预防:**
- 每次推送前检查选题是否符合定位
- 定期回顾已发布内容调整过滤规则

---

### 案例 3: 夜间任务堆积 (Proactive-Agent)
**触发:** 心跳检查发现 12 个夜间任务

**行动:**
1. ✅ 分析任务执行情况
2. ✅ 发现任务过多导致堆积风险
3. ✅ 提出精简方案 (12→3 个)
4. ✅ 使用正确流程更新配置
5. ✅ 验证新配置生效

**预防:**
- 定期检查任务数量
- 合并相似任务
- 禁用不必要任务
