# 数据源改进经验教训

**日期**: 2026-01-31
**目的**: 记录数据源开发中的关键问题和教训

## 当前问题分析

### 1. 数据质量严重不足

**问题表现**：
- 大量 HTML 片段和网站导航元素被当作"提示词"收集
- 不完整的句子、CSS 代码、JavaScript 函数也被提取
- 很多"提示词"只是句子片段，没有实际用途

**根本原因**：
1. **提取逻辑过于宽松**：只要匹配简单的正则表达式就认为是提示词
2. **缺乏语义验证**：没有检查内容是否真的是一个有用的 AI 提示词
3. **HTML 解析不彻底**：没有正确清理网页内容，提取了很多噪音

### 2. 评分系统失效

**问题表现**：
- 明显垃圾内容（如 `"> Sign Up Open Menu. Close Menu."`）得 40 分
- 无意义片段（如 `"t do this again."`）得 25 分
- 平均分数在 45-60 之间，但大多数内容根本不可用

**根本原因**：
1. **基于关键词而非语义**：只检查是否包含 "specific", "detailed" 等词
2. **结构检查过于简单**：只看是否有冒号、换行等简单标记
3. **没有理解实际含义**：无法区分真正的提示词和随机文本

**经验教训**：
- **规则永远比 AI 差**：基于规则的评分系统无法理解上下文
- **应该使用 LLM 进行语义评估**：让 AI 判断内容是否真的有用
- **增加人工审核层**：至少抽样验证 10-20 条结果

### 3. 数据源单一且质量参差

**问题表现**：
- 主要依赖 SearXNG 网络搜索，来源质量不可控
- 抓取了 Reddit、博客、教程网站，但内容碎片化严重
- 很多内容只是介绍如何写提示词，而不是真正的提示词

**根本原因**：
1. **缺乏高质量数据源**：没有针对专业提示词库（如 PromptBase）
2. **搜索关键词不够精准**：搜索范围太广，噪声太多
3. **没有验证来源可信度**：抓取了低质量网站的内容

### 4. Twitter API 限制问题

**问题表现**：
- 免费 Twitter API 有严格的速率限制（429 错误）
- 限制：每月 500,000 条推文，每 15 分钟 300 条请求
- 实际可用数据量远低于预期

**解决方案**：
1. **考虑升级付费计划**：或者使用其他 Twitter 数据提供商
2. **添加代理池**：使用多个 API key 轮换
3. **优化查询策略**：减少不必要的请求，批量处理

## 关键教训

### 教训 1：数据清洗比数据收集更重要

**问题**：我们花了很多时间收集数据，但没有花足够时间清洗数据。

**改进**：
- 在数据收集阶段就要有严格的过滤规则
- 收集后必须进行人工抽样验证
- 宁可少收集，也要保证质量

### 教训 2：LLM 比规则更适合内容评估

**问题**：试图用规则和关键词来评估提示词质量，结果失败。

**改进**：
- 使用 Claude/GPT 等 LLM 进行语义评估
- 设计好的评估 prompt，让 AI 判断内容是否真的有用
- 保留 AI 的评估理由，便于调试

### 教训 3：需要分层的数据源策略

**问题**：所有数据源同等对待，没有区分优先级。

**改进**：
- **Tier 1（高质量）**：专业提示词网站（PromptBase、LearnPrompting）
- **Tier 2（中等质量）**：技术博客、GitHub 仓库
- **Tier 3（补充）**：社交媒体、论坛、Reddit

### 教训 4：自动化的边界

**问题**：试图完全自动化整个流程，忽略了人工验证的必要性。

**改进**：
- 定期人工抽查自动化结果
- 建立"黄金数据集"作为质量基准
- 发现问题后快速调整自动化流程

## 改进方案

### 短期改进（1-2 周）

1. **改进数据提取逻辑**
   - 添加更严格的正则表达式验证
   - 过滤明显的非提示词内容（HTML、CSS、JS）
   - 添加最小长度和最大长度限制

2. **使用 LLM 重新评估**
   - 用 Claude 对已有数据重新评分
   - 设置更严格的评分标准（≥80 才保留）
   - 保留 AI 的评估理由

3. **优化搜索关键词**
   - 更精准的关键词（如 "GPT-4 prompt template", "Midjourney prompt example"）
   - 添加特定场景关键词（"marketing", "coding", "creative writing"）
   - 过滤关键词（去除 "how to", "tutorial", "guide"）

### 中期改进（2-4 周）

1. **添加高质量数据源**
   - 抓取 PromptBase.com（需要爬虫）
   - GitHub awesome-prompts 仓库
   - LearnPrompting.org 教程示例

2. **建立质量监控**
   - 每周人工抽查 50 条数据
   - 统计准确率，调整自动化流程
   - 建立"坏词列表"（自动过滤）

3. **改进评分系统**
   - 5 维度评分：实用性、创新性、完整性、热度、作者影响力
   - 使用 LLM 进行语义评估
   - 保留评估过程和理由

### 长期改进（1-3 个月）

1. **建立自动化质量保证**
   - 持续监控数据质量指标
   - 自动检测异常模式
   - 定期重新评估历史数据

2. **数据源多样化**
   - 开发专用爬虫
   - 合作获取高质量数据
   - 用户贡献和反馈系统

3. **建立提示词分类体系**
   - 按用途分类（文本、图像、视频、代码等）
   - 按难度分类（初级、中级、高级）
   - 按行业分类（营销、开发、创意等）

## 总结

**最重要的教训**：
1. **质量 > 数量**：100 个高质量的提示词 > 10,000 个低质量的
2. **LLM > 规则**：内容评估必须使用 AI，不能用简单的规则
3. **人工验证不可替代**：自动化需要定期人工抽查和调整
4. **数据源要有优先级**：不是所有数据都同等重要
